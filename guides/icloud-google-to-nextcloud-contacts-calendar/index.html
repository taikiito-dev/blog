連絡先とカレンダーをiCloud・GoogleからNextcloudに移す

iCloud連絡先81件・Google連絡先553件をNextcloud Contactsへ、Googleカレンダーの個人予定232件をNextcloud Calendarへ移した記録。前半は何を決め、何を選ばなかったか。後半の手順（アプリパスワードの発行からCalDAV/CardDAVへ直接PUTするコマンドまで）はClaudeが書き、実行して確かめたもの。

連絡先とカレンダーを、Nextcloudの標準機能(Contacts・Calendar)に一本化した記録。すでにファイル(前の記事)で使っていたNextcloudに機能を足すだけなので、新しいサーバーを立てる作業は無かった。

先に役割を書いておく。コマンドを書いたのはClaude(AnthropicのAIアシスタント)で、私は決める側をやった。 手順を考えなくていいぶん、「どのデータを移し、どれを残すか」だけをじっくり考えられた。だからこのページも、前半に判断、後半に実際の手順という形にしてある。

この記事でやること — iCloudとGoogleに分かれていた連絡先633件と、Googleカレンダーの個人予定232件を、CardDAV/CalDAVのエンドポイントへ1件ずつPUTしてNextcloudへ移す。手順はページ後半にまとめた。

前提#

すでにNextcloudが動いていることを前提にする。まだの場合は先にファイルをGoogle DriveからNextcloudに移すを読んでほしい。

何をしたかったか#

連絡先はiCloudとGoogleの両方に分散していた。カレンダーは個人の予定をGoogleカレンダーで管理していた。どちらも「今後もGoogle/Appleに預け続けるほどの理由がない」データなので、ファイルや写真と同じ流れでNextcloudに集約することにした。同期方式は特定の会社に縛られない業界標準の規格(CardDAV・CalDAV)なので、Mac標準の「連絡先」「カレンダー」アプリやiPhoneからもそのまま繋げられる。

決定1 — Web UIのインポートをやめ、CardDAV/CalDAVへ直接PUTした#

日付 2026年9月12日

迷ったこと 連絡先633件・カレンダー232件を、Nextcloud Web UI(ブラウザ上の管理画面)のインポート機能で読み込ませるか。

採った案 CalDAV(カレンダーの同期方法を定めた業界標準規格)・CardDAV(連絡先の同期方法を定めた業界標準規格)のエンドポイント(データの送り先URL)へ、1件ずつPUT(データをサーバーへ送り込む処理)する方式に切り替えた。 地道なやり方だが、Web UIのインポートより確実に反映される。

却下した案 Web UIの「連絡先をインポート」「カレンダーをインポート」機能。

なぜ却下したか 実際に試して通らなかったからだ。連絡先は件数が多いと不安定だった。カレンダーは.icsファイルを読み込ませたところ「could not be parsed」(うまく読み取れなかった、というエラーメッセージ)で止まり、.icsファイルの行折り返し(RFC5545というカレンダーデータの技術仕様で決められたルール)を手直ししても解決しなかった。

後から見た当たり外れ 当たり。連絡先633件・カレンダー232件、全てこの方式で成功した。

残った教訓 Web UIの一括インポートは大量データに弱い。 少数なら問題ないと思うが、数百件規模ならCalDAV/CardDAVへ直接PUTする方式を最初から選んだ方が早い。

決定2 — もう1人と共有しているカレンダーは、Googleに残した#

日付 2026年9月12日

迷ったこと カレンダーをどこまでNextcloudへ移すか。

採った案 個人の予定232件だけを移し、反映を確認したうえでGoogle Calendar側の元データは削除した。自分以外にもう1人が使っている共有カレンダーはGoogleに残した。

却下した案 共有カレンダーも含めて全部移す。

なぜ却下したか 相手がGoogle前提で使っているためだ。ファイル移行の時の「移す理由が移さない理由に勝つものだけ移す」という基準を、ここでも踏襲した形だ。

残った教訓 自分だけのデータと、相手のいるデータは同じ基準では動かせない。移さない判断も移行の一部だ。

つまづいた所と積み残し#

.well-known/carddavのリダイレクトが失敗する: macOSは通常、サーバーアドレスを短く入力するだけで.well-known/carddavという決まったパスへ自動でアクセスし、正しいCardDAVのURLへリダイレクトしてくれる仕組みになっている。ところが、Cloudflare経由のリダイレクト処理の影響で、この自動検出がうまく機能しなかった。自動検出をあきらめてフルパスを直接指定することで解決した(後半のStep 4参照)。同じ症状はCalDAV側(.well-known/caldav)でも起こりうるので、うまくいかない場合は同じ対処(フルパス直接指定)を試すとよい。

積み残しもある。毎年同じ日に繰り返す記念日のような予定は、Google側で表示されていた2025〜2029年分のインスタンスだけを削除しており、繰り返しルールそのもの(マスター)は消していない。2030年以降にまた自動で出現する可能性があるため、気になったら改めてGoogle Calendar側で対応する必要がある。また、Gmailにはフライトやレストランの予約確認メールを自動でGoogleカレンダーに追加してくれる機能があるが、これは自前のメール+Nextcloudカレンダーの組み合わせには存在しない、Google独自の仕組みで、メール・カレンダーのどちらか片方だけ移しても再現できない。同等の仕組みを自作するなら別プロジェクトになるので、今回は見送っている。

結果#

連絡先633件・カレンダー232件、どちらも移行完了。MacとiPhoneから、Google/iCloudの時とほぼ変わらない感覚で使えている。大量データの移行はWeb UIのインポートを過信せず、CalDAV/CardDAVへの直接PUTを検討するとよい、というのが一番の学びだった。

手順#

ここから下はClaudeが書き、自分の環境で実行して結果を確かめたものだ。2026年9月の版で、実際にこれで連絡先633件・予定232件が移った。

置いておく理由は2つある。ひとつは、作業の全体像と長さが先に分かること。見てのとおり、アプリパスワードの発行からカレンダー移行まで5段階の話だ。もうひとつは、自分が使っているAIに「これと同じことをやりたい」と渡す材料になること。ゼロから説明するより、動いた実例を見せたほうが早いし、あなたの環境に合わせた形に直してくれる。

Step 1: Nextcloudのアプリパスワードを発行する#

まず、CardDAV/CalDAV経由でアクセスするための専用パスワードを発行する。Nextcloud本体のログインパスワードをそのまま外部アプリに渡すのは避け、用途ごとに無効化できる「アプリパスワード」を使うのが基本。

Nextcloudの画面右上のアイコン → 個人設定(Personal settings) → セキュリティ(Security) → 「新しいアプリパスワードを作成」から、名前(例: contacts-migration)を付けて発行する。表示されたパスワードは、この画面を閉じると二度と表示されないので、一時的にメモしておく。

Step 2: 連絡先をエクスポートする(633件)#

Google連絡先553件・iCloud連絡先81件を、それぞれvCard形式(連絡先データの標準的なファイル形式、拡張子.vcf)で書き出す。

  • Google連絡先: contacts.google.com → 左メニュー「エクスポート」→ vCard形式を選択
  • iCloud連絡先: icloud.com → 連絡先 → 全て選択 → 右下の歯車アイコン → 「vCardを書き出す」

重複1件を除いた633件を、まとめた1つの.vcfファイルにしておく(vCard形式は複数の連絡先を1ファイルに連結できる)。

Step 3: CardDAVへ直接PUTする#

決定1のとおり、Web UIのインポートではなくCardDAVのエンドポイントへ1件ずつ送り込む。

まず、まとめた.vcfファイルを連絡先1件ずつのファイルに分割する(Pythonのvobjectライブラリや、csplitのようなテキスト分割コマンドで、BEGIN:VCARD〜END:VCARDの区切りごとに切り出す)。分割できたら、1件ずつ以下のようにアップロードする。

curl -u "admin:<Step1のアプリパスワード>" \
  -X PUT \
  --data-binary @contact-001.vcf \
  -H "Content-Type: text/vcard; charset=utf-8" \
  "https://drive.example.com/remote.php/dav/addressbooks/users/admin/contacts/contact-001.vcf"

これを633件分、シェルスクリプトのforループなどで繰り返す。1件ずつリソースとしてサーバーに送り込む地道なやり方だが、Web UIのインポートより確実に反映される。

Step 4: Macで連絡先を同期する#

Macの「連絡先」アプリ → 環境設定 → アカウント → 「アカウントを追加」→「他のアカウント」→「CardDAVアカウントを追加」。

ここで前述の.well-known/carddavの件にハマった。解決策: サーバーアドレスの欄に、自動検出用の短いURL(drive.example.com)ではなく、以下のフルパスを直接入力する。

https://drive.example.com/remote.php/dav/principals/users/admin/

ユーザー名はadmin(Nextcloudのユーザー名)、パスワードはStep 1で発行したアプリパスワードを使う。iPhoneの「連絡先」アプリでも同じ設定項目がある。

Step 5: カレンダーの移行(232件)#

個人用のGoogleカレンダーに入っていた予定(2019〜2029年、232件)をNextcloud Calendarの「Personal」カレンダーへ移す。

まずcalendar.google.comの設定画面から、対象のカレンダーを.icsファイル(カレンダーの予定データをやり取りするための標準的なファイル形式)としてエクスポートする。

決定1のとおり、Web UIのインポートは通らなかったので、連絡先と同じくCalDAVへ直接PUTする。.icsファイルを1イベントずつに分割し(BEGIN:VEVENT〜END:VEVENTの区切りで切り出す)、以下のようにアップロードする。

curl -u "admin:<アプリパスワード>" \
  -X PUT \
  --data-binary @event-001.ics \
  -H "Content-Type: text/calendar; charset=utf-8" \
  "https://drive.example.com/remote.php/dav/calendars/users/admin/personal/event-001.ics"

232件全てこの方式でアップロードしたところ、全て成功した。反映の確認後にGoogle側の元データをどう扱ったかは決定2に書いた。
